# Hand-off: P5 and P6b (PR 51), what waits for P6a and P8

The local API server runs in `gazpacho`, and the interface follows `spec/local-api.md` draft 5. This note lists what this branch could not finish because the core does not emit its view objects yet (P6a) or has no signing yet (P8). Each item names the test or check that will show when it is done.

## Waiting for P6a (the core's view objects and the API engine)

1. **The multi-process test is off.** `tests/web/multiprocess.spec.mjs` is marked fixme. CI already builds `gazpacho-test` and sets `GZ_PROGRAM`, so removing the fixme line is enough to run it. Two checks fail if it stays off after P6a:
   - `web_p6a_fixme`, from the sources;
   - `program_lobby`, from the views the program actually received.
2. **Held calls answered from command results.**
   - `gzp_api_send_command` and `command_result` in `program/api.c` have no caller yet: every acting call answers `501 not_in_this_release` with `params.needs`.
   - P6a's first acting call should add a `program_api` case that goes through them: request id match, error codes, and clearing on `node_starting`.
3. **The words-check limit is not saved** (review of PR 51, L4). `words_checks_left` answers 3 after every start, so the limit of three checks per 24 hours (12.3) resets with the program. The journal record `words_check_attempts` belongs to P6a's API engine.
4. **Lock while signing is held.** Lock now stops the node and starts it again on unlock (unlock.h, review M5). Local-api.md 4.7 also says a lock is held while signatures are out (`held_for_signing`). The program cannot tell that until the core reports its rounds, so it locks at once. P6a: answer the lock with `held_for_signing` while any round of this node is in Signed or Unfinished.

## Waiting for P8 (keys and signing)

5. **`seed()` (unlock.h) has no caller yet.** The key port will call it. The caller wipes the 64 bytes. With the stand-in, the seed is derived from `wallet-seed.standin`.

## Recorded, not this branch's

6. **The release binary still holds the journal stand-in (`gzp_standin_*`) and the name `wallet-seed.standin`** (review L5). Both are older than this branch: `main.c` reads the plaintext seed file until encrypted storage (branch s5-s6-program) replaces it. The unlock stand-in is not in the release binary.
