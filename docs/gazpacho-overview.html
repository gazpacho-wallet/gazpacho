Gazpacho Wallet

One program that lets anyone join a SuperScalar channel factory, or host one. No Bitcoin node, no separate Lightning node, no modified software.

Planning stage · first release is signet-only

The missionGet SuperScalar into people's hands

A channel factory lets many people share one on-chain output, and each of them gets a Lightning channel from it. Gazpacho is the front door: a professional proof-of-concept wallet that shows what that makes possible.

For everyone

Self-contained

Install one thing. It carries its own small Lightning node and reads the chain from public servers.

Two roles

Join or host

The same software lets you be a member of a factory or the host that funds and runs one.

Your keys

Leave any time

A member can always exit on chain without the host's help. That is the goal the design is built around.

Reuse

The foundations

Factory tree, group signing, timelocks, transaction and script builders, keys, recovery phrases, invoices, fee bumping. Imported as the start of the core.

Rebuild

The moving parts

Ceremonies, channel state, rotation, message format, database, watching. Shown to work on signet with 127 members, but tangled together and with known safety gaps. Rewritten cleanly, using the old code as the reference.

Leave behind

The extras

Gossip, route-finding, a light client that does not work, JIT channels, splicing. Not needed for the first releases.

Soup wallet is mothballed. We keep its ideas: a host publishes its terms, and the wallet refuses to sign anything outside the user's limits.

The shapeOne portable core, thin shells

Almost everything is C. The one exception is the screens of the local web interface, which a browser requires to be HTML and JavaScript. Keys and channel state stay in the C program.

core/    the library: tree, signing, ceremonies, channel, wallet, terms

Seeing the chainThe Sparrow model

Default

Public servers

Nothing to install. Gazpacho asks more than one server and compares the answers.

Better

Point Gazpacho at an Electrum server you run.

Best

Your own Bitcoin node

No third party sees what you watch. Recommended for every host.

Keys never leave the app in any of the three. While Gazpacho is running it also watches the factory and channel outputs itself and responds if an old state is published.

DecidedWhat is settled

  • Gazpacho is both member and host software. Soup wallet is mothballed.
  • First release is signet-only. Mainnet code is present but switched off.
  • One funder per factory at first: the host. Members start at zero.
  • The full layered SuperScalar tree in the first release. Pseudo-Spilman leaves. JIT channels off.
  • Lightning's own wire language and its standard taproot channel format.
  • Factories form in a lobby, like a game server. Listings and host proofs live on Nostr.
  • A host links to a regular Lightning node through an adapter; every major node is to be supported.
  • The screens are a local web interface over a C program.
  • Protection while away: about two weeks to open the app; a separate watching service later.
  • As much C as possible. Quality first, no deadline.
  • Home: github.com/gazpacho-wallet/gazpacho, MIT licence.

Still openIn progress

  1. The lobby's details: voting, removal, deposits, reputation. Research is under way.
  2. Which public chain servers ship in the default list.
  3. The shared message specification, to be written and offered to the SuperScalar repo.
Honest limits. Nothing here is built yet. The reference code this starts from has known safety gaps that another team is fixing, and "a member can always leave" is the design goal, not yet the proven state of the code. That is why the first releases are signet-only.
