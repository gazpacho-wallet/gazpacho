# Review ledger

Every independent review of a pull request or a specification, one row per piece of work and one line per round. Started 2026-11-12 after the gap review found reviews archived on the wrong branch or not at all; brought up to date the same day (truth pass), after PRs 7, 10, 11 and 12 merged.

Every reviewer is an agent that did not write the work. No review has been posted on GitHub itself; the files here are the record. GitHub's branch protection requires the 11 CI checks but no approving review, so this file is the only place the review rule is kept.

**Rule**, from `PLAN.md` ("How work proceeds": fixes, then a second review of what changed, then merge) and `SLICE1-WORK.md`: no merge while a high or medium finding is open, while the review of the fixes is missing, or while CI is red or missing.

**How the merges of 2026-11-12 measure against it.** CI was green (all 11 required checks) on the merged head of each of PRs 7, 10, 11 and 12. Every high and medium finding was answered by a fix commit. But the rule was not fully met on paper:

- **PR 7:** the last round (round 3) confirmed the fixes **by reading the code only**. Its reruns finished after the verdict; their results are summarised below and were never judged by the reviewer.
- **PR 10:** round 2 confirmed the fixes of round 1 with runs. The builder's later commits answering round 2's own findings (N1 to N6) were **not reviewed** before the merge; only CI checked them.
- **PRs 11 and 12:** round 2 confirmed the fixes of round 1 with runs and asked for one more fix (the libFuzzer job). That fix commit was **not reviewed**; only CI checked it.
- The final rounds of PRs 7, 10 and 11 were archived only after the merge, in this update.

Update this file in the same pull request as each new review.
